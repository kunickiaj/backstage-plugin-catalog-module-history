## Backend E2E setup

The default loader includes the Postgres history store. Keep existing provider-wrapper wiring and add a wrapper at each provider registration when provider-origin capture is needed.

```yaml
catalog:
  history:
    api:
      enabled: true
```

Routes require authenticated users and the `catalog-history.read` permission. When the permission framework is enabled, return an explicit `ALLOW`; global history can include metadata for deleted entities and does not mirror live-catalog visibility.

Fresh schemas apply all three history migrations; existing development data applies pending migrations at startup. Back up data needed before an upgrade. The global-feed index builds during normal startup and can block history-entity writes on large retained histories, so schedule a maintenance window before deployment.

Processing capture does not observe deletes; provider capture records mutations that flow through the wrapped provider. The opt-in reconciler can later record an observed disappearance from its own prior baseline. Direct entity deletion and location unregistration, including **Unregister** actions, do not guarantee a delete event; see the [known deletion-capture limitation](../../README.md#known-deletion-capture-limitation).

Retention limits, garbage collection, and large-history scale behavior are not supported release claims.

## Frontend E2E setup

Register the default plugin through the host application's existing NFS feature and discovery setup. Keep existing features; do not replace them or add a legacy Material UI route.

```ts
import { createApp } from '@backstage/frontend-defaults';
import catalogHistoryPlugin from '@kunickiaj/backstage-plugin-catalog-history';

export default createApp({
  features: [
    // Existing NFS features stay here.
    catalogHistoryPlugin,
  ],
});
```

Load the BUI stylesheet once if the host does not already do so:

```ts
import '@backstage/ui/css/styles.css';
```

The entity tab is scoped to the current catalog entity. The global page is `/catalog-history` and can show retained events for entities deleted from the live catalog.

Updates compare the saved snapshot with the immediately preceding saved snapshot for the same entity, source, and provider. A delete has no deletion payload; **Last recorded snapshot before deletion** is the prior saved state, not a deletion snapshot.

## E2E status

Host E2E work is in progress. This guide describes the setup and expected checks; it does not claim that host E2E has passed.

- Use published exact package versions in an authorized disposable consumer workspace.
- Check startup migrations and backups for older data, the default backend loader and service overrides, and provider/reconciler capture.
- If the existing host policy enables them, check authenticated API access, explicit permission decisions, unauthenticated rejection, and rejected permissions without changing that policy.
- Check NFS and BUI setup, React `^18.3.1` peers, the global and entity pages, filters, detail view, and delete-capture label. A preview does not replace this installed-package smoke check.

See [Publishing packages](../publishing.md) for archive inspection, exact-version and `latest` verification, provenance limits, release notes, and recovery rules.
