# `0.3.0` release preparation

`0.3.0` is prepared for publication. It has not been published to npm yet. It will release all five public packages together from `main` after the normal validation and trusted-publishing procedure.

## Changes since `0.2.0`

- The global history page now shows structured recorded event details and badges for recorded changes to owner, relations, status, and orphan state.
- Provider discovery suggests full provider names from retained history, including deleted entities. Entity and Kind discovery also reads retained history; entity-name prefixes are literal and case-insensitive.
- The read API can list recording cycles and retrieve a cycle with its retained changes. The frontend can open a cycle view with `?cycleId=`.
- The API adds timestamp as-of reads. The frontend does not use this endpoint.
- The default Postgres store applies a per-statement timeout to history reads; `catalog.history.api.queryTimeoutMs` defaults to 10 seconds.
- Four optional OpenTelemetry instruments are available through Backstage's `MetricsService`. See [Observability](../observability.md).
- An omitted reconciler `schedule` uses the hourly frequency, 10-minute timeout, and 30-second initial delay. Omitted keys in an explicit schedule inherit those defaults. An explicit schedule without `initialDelay` now waits 30 seconds before its first run; use `initialDelay: { seconds: 0 }` to start immediately.
- [Sizing guidance](../sizing.md) covers retained-row estimates, capture-layer volume, and database capacity planning.

## Upgrade notes

Migration `20261025000000_entity_discovery_name_index.js` creates a regular, non-concurrent name-prefix index and runs `ANALYZE` during schema bootstrap. History entity writes wait for the migration to finish. Back up first and schedule a maintenance window before upgrading a large retained history. See the [entity-discovery name-index notes](../../packages/catalog-history-backend/README.md#entity-discovery-name-index-in-030).

The [known deletion-capture limitation](../../README.md#known-deletion-capture-limitation) and unsupported [retention and garbage collection](../sizing.md#plan-retention-as-a-separate-change) still apply.

## Compatibility

All five packages support Node 22 and 24. Backend dependencies are aligned with Backstage 1.56.2, for example `@backstage/backend-plugin-api` `^1.11.0` and `@backstage/plugin-catalog-node` `^2.2.6`; check that your backend resolves compatible versions before upgrading. The frontend still targets NFS `0.18.2`, `@backstage/plugin-catalog-react` `3.3`, Backstage UI `0.19`, and React 18.
